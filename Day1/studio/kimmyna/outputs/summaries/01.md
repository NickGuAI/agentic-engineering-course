# Lecture 01 — Uninformed Search (COMS W4701, Lecture 3)

## Core Concepts

### Search Problem

- The lecture restricts itself to task environments with a specific set of Task Environment Properties: fully observable, single-agent, deterministic, static, and discrete [p.3]
- Under those properties the agent has "perfect" percepts and a known transition model, so nothing has to be inferred or estimated [p.3]
- States describe the agent's possible configurations as well as the goal, so a Goal-Based Agent can search for a state sequence leading to the goal state [p.3]
- Once the sequence is found the solution is fixed, and the agent essentially becomes a reflex agent: no need to update models or learn from experience [p.3]
- A Problem-Solving Agent is therefore one that solves search problems to find discrete sequences of states and actions between initial and goal states [p.22]
- Formally, a search problem is a state space 𝑆, the set of descriptions of the agent and environment [p.4]
- It has one Initial State and one or more Goal State entries [p.4]
- Goal Test is a function 𝑆 → {𝑇𝑟𝑢𝑒, 𝐹𝑎𝑙𝑠𝑒}, e.g. 𝑖𝑠𝐺𝑜𝑎𝑙(𝑠1) = 𝐹𝑎𝑙𝑠𝑒 [p.4]
- Action Set gives the legal actions at each state, e.g. 𝐴𝑐𝑡𝑖𝑜𝑛𝑠(𝑠1) = {𝑎1, 𝑎2, 𝑎3} [p.4]
- Transition Model is a function 𝑆 × 𝐴 → 𝑆, e.g. 𝑅𝑒𝑠𝑢𝑙𝑡(𝑠1, 𝑎1) = 𝑠2 [p.4]
- State-Action Cost Function is a function 𝑆 × 𝐴 → ℝ, e.g. 𝐶𝑜𝑠𝑡(𝑠1, 𝑎1) = 10 [p.4]
- An Optimal Solution is one that minimizes total cost among all state sequences [p.4]
- [보충] These six pieces are what any concrete puzzle must be reduced to before any algorithm in this lecture can be applied; the algorithms differ only in the order they visit states, never in this formulation
- Grid World Path Finding instantiates all six: state is the rabbit's coordinates, 𝑆 = {(𝑥, 𝑦) | 𝑥 ∈ {0,1,2,3}, 𝑦 ∈ {0,1,2,3,4}} [p.5]
- Its goal test is 𝑖𝑠𝐺𝑜𝑎𝑙((3,3)), its actions are Up/Down/Left/Right, and every action costs 1 [p.5]
- Its transition model is 𝑅𝑒𝑠𝑢𝑙𝑡((𝑥, 𝑦), Up) = (𝑥, 𝑦 + 1), and it can encode walls by mapping a blocked move back onto itself, e.g. 𝑅𝑒𝑠𝑢𝑙𝑡((0,0), 𝐿𝑒𝑓𝑡) = (0,0) [p.5]
- The n-puzzle instantiates them differently: state is the locations of all tiles and the blank, the action is one of 4 directions for the blank tile, each step costs 1, and the goal test asks whether the current state equals the goal state [p.6]
- Other examples include Route-Finding such as vehicle navigation, and robot navigation in the real world [p.7]
- Touring Problems such as the traveling salesperson, and layout and assembly sequencing problems, are also search problems [p.7]
- Mathematical puzzles and proofs give infinitely large state spaces, such as Knuth's Conjecture (1964) that any positive integer can be obtained by combining factorial, floor, and sqrt operations on the input 4 [p.7]

### State Space Graph

- The state space can be abstracted as a directed graph [p.8]
- States are represented as vertices/nodes [p.8]
- Transitions are represented as edges/arcs [p.8]
- Costs are represented by edge weights [p.8]
- A solution is then a path from the initial state to a goal state [p.8]
- State spaces can be very large or infinite, so this graph is rarely built or stored in full in memory [p.8]
- [보충] This is the key practical limitation that motivates everything that follows: the graph is the object we reason about mathematically, but not the object the algorithm gets to hold

### Search Tree

- Most search algorithms explore paths by incrementally constructing a search tree from the initial state [p.9]
- Internal nodes have already been explored [p.9]
- Important: unexplored nodes are not in memory [p.9]
- For explored nodes, the tree structure records the unique path to each one from the initial state [p.9]
- [보충] The graph describes the problem, while the tree describes one particular exploration of it, so a single state can appear as several distinct tree nodes arrived at by different paths

### Frontier

- Leaf nodes lie in a frontier data structure, and frontier nodes are the candidates for expansion [p.9]
- The search strategy determines the ordering for popping frontier nodes [p.12]
- Different strategies yield different efficiencies and guarantees [p.12]
- Frontier implementation examples include LIFO (a stack) and FIFO (a queue) [p.12]
- It can also be a Priority Queue using a general Evaluation Function 𝑓(𝑛) [p.12]
- [보충] Every algorithm later in the lecture is the same loop with a different frontier ordering, which is why the choice of data structure, not the code around it, is what determines the guarantees

### Node Expansion

- Expansion of a frontier node means creating and adding its children to the tree [p.10]
- It iterates over all possible actions, and the transition function tells us each resultant state [p.10]
- It may also compute and store the cumulative cost up to the new node [p.10]
- In the general case a node has four components: state, parent node, action, and cost [p.10]
- The main idea of Best-First Search is to repeatedly pop nodes out of the frontier, expand new children nodes, and insert them into the frontier [p.11]
- It initializes the current node to contain the initial state and the frontier as a queue data structure [p.11]
- It runs until either the goal test is successful or we run out of nodes to expand [p.11]
- The goal test is applied BEFORE expanding the current node [p.11]
- We may also want to apply Pruning to make the search space smaller [p.12]
- There may be multiple paths to a state, so we should check whether a state has already been reached before placing it into the frontier [p.12]
- The set of seen states, reached, may be implemented as a lookup table (dictionary) mapping states to nodes [p.13]
- With pruning, we only add a new node to the frontier and to reached if it was not previously reached [p.13]
- [보충] The frontier and reached play different roles and are not interchangeable: the frontier holds nodes still waiting to be expanded, while reached records every state already seen, so a state can be in reached without still being in the frontier

### Depth-First Search

- The idea is to expand the deepest node in the frontier, disregarding action costs [p.14]
- Its frontier is implemented as a stack (LIFO), or as a priority queue where 𝑓(𝑛) = −𝑑𝑒𝑝𝑡ℎ(𝑛) [p.14]
- Its behavior ends up searching each path to completion, and if no goal is found it backtracks and proceeds along a new path [p.14]
- On Optimality: DFS is not optimal, as there is no guarantee of a least-cost solution [p.14]
- On Completeness: DFS is not complete, as there is no guarantee of finding a solution if one exists or of correctly reporting failure otherwise [p.14]
- [보충] The incompleteness is a consequence of the stack ordering rather than a bug: an infinite or cyclic path can be descended forever, so the algorithm never returns to the branch that held the goal
- Suppose the search tree has Branching Factor 𝑏 and max depth 𝑚 [p.15]
- Its Time Complexity is the worst-case number of expanded nodes, 𝑂(𝑏^𝑚) [p.15]
- Its Space Complexity is the worst-case number of frontier nodes in memory, 𝑂(𝑏𝑚), because there is one node in each of 𝑚 tiers with 𝑏 successors each [p.15]
- Good use cases for DFS are when space is restricted, or when many goals exist and we just want to find one fast [p.15]

### Breadth-First Search

- The idea is to expand the shallowest node in the frontier, disregarding action costs [p.16]
- Its frontier is implemented as a FIFO queue, or as a priority queue where 𝑓(𝑛) = 𝑑𝑒𝑝𝑡ℎ(𝑛) [p.16]
- BFS is complete and will eventually find a goal if one exists [p.16]
- BFS returns the shallowest solution, e.g. at depth 𝑑 [p.16]
- It is optimal if action costs are uniform [p.16]
- Its worst-case time and space complexities are both 𝑂(𝑏^𝑑) [p.16]
- Good use cases for BFS are when the problem or state space is small, or when the solution is close to the start [p.16]
- In comparison, DFS and BFS are both implementations of best-first search, with frontier nodes popped deepest-first and shallowest-first respectively [p.17]
- Both have exponential time complexity; BFS has exponential space complexity, while DFS space is linear in search tree depth [p.17]
- Neither is optimal in general, and BFS is only guaranteed to return the shallowest solution [p.17]
- A small optimization is the Early Goal Test, which checks upon insertion into the frontier rather than upon popping [p.17]

### Iterative Deepening (supporting algorithms)

- Depth-Limited Search prevents DFS from going past a set depth 𝑙 [p.18]
- Its time complexity is 𝑂(𝑏^𝑙) and its space complexity is 𝑂(𝑏𝑙) [p.18]
- It is not complete, because it will miss the goal if 𝑙 is set too small [p.18]
- Iterative Deepening Search iteratively performs depth-limited search, trying 𝑙 = 0, then 𝑙 = 1, and so on [p.18]
- It ends when 𝑙 reaches the shallowest solution at depth 𝑑 [p.18]
- Its space complexity is 𝑂(𝑏𝑑), and the strategy is now complete [p.18]
- More nodes are expanded than in depth-limited search, but the time complexity is still 𝑂(𝑏^𝑑) [p.18]
- Shallow depths are searched multiple times, but the lowest levels still dominate the node count [p.18]

### Uniform-Cost Search

- To find an optimal solution we need to consider path costs in the frontier ordering [p.19]
- Its frontier is implemented as a priority queue with evaluation function 𝑓(𝑛) = 𝑐𝑜𝑠𝑡(𝑛) [p.19]
- Nodes popped out earlier should have lower cost than nodes popped out later [p.19]
- When a goal is found, it is reached via the cheapest possible path [p.19]
- The deck also names it Dijkstra's algorithm, and works a 7-step example ending with solution 𝑆, 𝑎, 𝑓, 𝑑, 𝐺 at cost 9 [p.19]
- On updating the frontier: suppose a frontier node 𝑛 contains a state 𝑠 with cost 𝑐, and we then expand a different node 𝑛′ containing 𝑠 with a lower cost 𝑐′ [p.20]
- In that case we update the mapping between 𝑠 and 𝑛′ in reached [p.20]
- We add 𝑛′ to the frontier, and it is guaranteed to be popped before 𝑛 [p.20]
- So there are two scenarios for adding a node to the frontier: previously unencountered (not in reached), or already encountered BUT via a cheaper path just found [p.20]
- On UCS properties: let 𝐶* be the cost of the optimal solution, and let 𝜖 be a lower bound on all possible costs [p.21]
- Then 1 + ⌊𝐶*/𝜖⌋ is the max depth to traverse before finding the optimal solution [p.21]
- Its time and space complexity is 𝑂(𝑏^(1+⌊𝐶*/𝜖⌋)) [p.21]
- UCS is both complete and optimal [p.21]
- [보충] Setting every action cost to 1 makes UCS and BFS coincide, since ordering by accumulated path cost and ordering by depth then give the same pop order; this is the same condition under which the deck calls BFS optimal
- Overall, search problems are represented as graphs and/or trees, which we try to represent and search in a systematic and efficient manner [p.22]
- The various search strategies each have different tradeoffs in time complexity, space complexity, completeness, and optimality [p.22]

## Lecture Flow

The lecture builds one machine, then swaps a single part of it four times. It opens by
shrinking the world until search is even possible: a **Search Problem** [p.3] is only posed
in a task environment that is fully observable, single-agent, deterministic, static and
discrete. Because percepts are perfect and the transition model is known, the agent never
has to learn — it only has to find a sequence. That sequence is defined by six formal
pieces (initial state, goal test, actions, transition model, costs, and what makes a
solution optimal), and the grid world and the n-puzzle are shown back to back precisely to
demonstrate that wildly different puzzles reduce to the same six pieces.

Once a problem is formalized this way it can be drawn, and a **State Space Graph** [p.8]
is the drawing: states as vertices, transitions as weighted edges, and a solution as a path
through it. But the lecture immediately undercuts its own picture — real state spaces are
too large or infinite to build or store. That gap between the object we reason about and
the object we can afford to hold in memory is what forces everything that follows.

The response is to grow a fragment of the graph on demand. A **Search Tree** [p.9] is
constructed incrementally from the initial state, recording the unique path back to each
explored node, with unexplored nodes deliberately absent from memory. Its leaves are the
live edge of that fragment, and they are held in the **Frontier** [p.9] — the single data
structure that will end up carrying all the variation in the lecture, since the strategy for
popping from it is what distinguishes one algorithm from another.

Growing the tree by one step is **Node Expansion** [p.10]: pop a node, iterate its actions,
create the children, record state/parent/action/cost. Wrapped in a loop with a goal test
applied before expansion, this is best-first search — the generic skeleton. Pruning via a
reached table then patches the one flaw the tree representation introduces, that the same
state can be discovered along many different paths.

With the skeleton fixed, the rest of the lecture only changes the frontier's ordering.
**Depth-First Search** [p.14] makes it a stack and takes the deepest node, which buys linear
O(bm) space but costs both optimality and completeness. **Breadth-First Search** [p.16]
makes it a FIFO queue and takes the shallowest node, which recovers completeness and the
shallowest solution at O(b^d) space — the exact mirror of DFS's tradeoff. Iterative
deepening is inserted here as the compromise between the two: it keeps DFS's memory profile
while inheriting BFS's completeness, because the deepest tier dominates the node count
anyway.

All three, though, still disregard action costs, so none of them is optimal when steps cost
different amounts. **Uniform-Cost Search** [p.19] closes the lecture by making the frontier a
priority queue keyed on accumulated cost rather than depth. This single change forces the
one genuinely new mechanism in the lecture — a cheaper path to an already-reached state must
update the reached mapping and re-insert the node — and in exchange it is the only algorithm
here that is both complete and optimal, at a cost bounded by the ratio of the optimal
solution cost to the smallest possible step cost.
