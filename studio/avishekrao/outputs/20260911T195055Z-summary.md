# Rapidly scaling online storage to serve over 1 billion ChatGPT users

[Source](https://openai.com/index/scaling-storage-one-billion-users-part-one/) · Published September 11, 2026
Retrieved: 2026-09-11 19:50:55 UTC

- **Architecture:** OpenAI describes moving Habitat from a Python library into a central storage service. This reduced deployment coordination across product teams and centralized authorization, auditing, and storage routing.
  - **Latency:** CPU-heavy tasks delayed Python’s event loop even when database responses were fast. Engineers measured scheduling delays, reduced concurrency per process, and spread traffic across more workers.
  - **Load balancing:** Reusing the most recently returned connection repeatedly sent traffic to overloaded servers. Switching from LIFO to FIFO connection reuse interrupted this feedback loop and improved load distribution.
- **Design tradeoff:** Habitat restricts queries to predictable operations rather than arbitrary SQL. Complex analytical workloads use separate systems, protecting online serving from expensive queries while shifting some complexity to client teams.
  - **Migration:** OpenAI reports that its Rust replacement handles 95% of production requests, using CPU six times and memory fifteen times more efficiently than Python. These are company-reported results, not independently verified benchmarks.
