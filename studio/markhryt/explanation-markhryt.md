The job is a small Python pipeline that runs in three steps: ingest, summarize, output. When you run run_job.py, it reads the three sources defined in the config, which are the Anthropic News and Engineering listing pages and the OpenAI RSS feed, since openai.com blocks scripts from reading its HTML. It parses each listing into article records, throws away any URL it has already seen according to a small JSON state file, keeps the newest ten per source, and then downloads the full text of each Anthropic article with a lightweight HTML-to-text parser. Those articles go to a summarizer in batches of eight. If an API key is available it asks laude for a structured JSON summary, a headline, a "why it matters" line, and tags for each piece, then makes one more call to write an overview and a few cross-cutting themes. If there is no key, or the model refuses or returns something unparseable, it quietly falls back to grabbing the first couple of sentences of each article instead. Finally it renders everything into a Markdown digest, saves it with a timestamp alongside a JSON copy, refreshes latest.md, marks every listed URL as seen so old backlog never leaks into future runs, and appends a one-line trace of the run to a log. A loop flag and a couple of cron and launchd files let it repeat every six hours, and the tests run entirely offline against fixture HTML with a fake fetcher.
