# Delegation Card

## Task

Create and update a personal HTML study guide for a course I specify, organized lecture by lecture. On each run, download the relevant course files, read the complete local PDF and PowerPoint files, digest any new or changed lecture materials, and write one separate HTML file per completed lecture under `outputs/<course-id>/`. Keep `study-guide.html` as a navigation index only.

## Context

For each run, I will provide a CourseWorks course ID or course files URL; the example link is not a fixed source. Find that course's lecture materials, using its Lectures folder when present. Use only materials I can access through my authenticated CourseWorks session or files I provide locally. Download the original PDF, PPT, and PPTX files into `outputs/<course-id>/sources/`. Read the downloaded files directly with local document tools, covering every page or slide and checking diagrams, figures, tables, and formulas as well as text. The audience is me, a student reviewing one lecture at a time. Put a brief lecture structure or outline at the top of each lecture section. Then explain the key ideas, formulas, and mechanisms in a way that helps me review and recall them. Include diagrams where they clarify a relationship or process, define important terms and symbols, work through important examples when the source supports them, and add a few self-check questions. Link each lecture section to the source files used.

## Success criteria

The HTML files open locally and identify the course supplied for that run. Each fully read lecture has its own stable file, such as `lecture-2.html`, with a brief outline, source-grounded explanations, clear diagrams where useful, and self-check questions. Formulas display correctly, symbols are defined, and diagrams have text labels or descriptions. Each lecture file identifies its source files and relevant page or slide numbers, links to the course index and the other completed lectures, and is linked from `study-guide.html`. A separate run report for each lecture, such as `lecture-2-run-report.md`, records the supplied course ID or URL; that lecture's downloaded files and total page or slide counts; pages or slides actually processed; completion status; files skipped or inaccessible; and changes since the previous run for that lecture. `run-report.md` is a navigation-only index linking to the lecture reports. I can inspect each report and trace for full page or slide coverage and compare lectures without mixed histories.

## Restrictions

- If my request does not clearly identify which course to digest, pause and ask me to confirm the course ID or CourseWorks URL before accessing files or creating a guide. Do not guess from prior runs or nearby courses.
- Do not request, store, or expose my password, session cookies, or API tokens. Do not bypass CourseWorks access controls.
- Download PDFs from the authenticated CourseWorks file-detail page (`/courses/<course-id>/files/<file-id>`) using its visible "Download <filename>" link. Try an actual mouse click in the native Chrome window and allow at least five seconds for the file to appear. If it does not, inspect Chrome's download indicator and any permission prompt before concluding that the file is inaccessible. During the Lecture 4 retry, Chrome showed a blocked-download indicator and a prompt about multiple automatic downloads; once CourseWorks downloads were allowed, a native mouse click on `Download 4-AI_uninformed.pdf` produced the complete local PDF. Ask me before changing a persistent browser permission such as "Always allow ... to download multiple files"; do not bypass a browser security warning. A browser-tool `downloadMedia()` call may return without error yet save no file (as it did for Lectures 3 and 4), while it did save Lecture 2 previously. Treat neither a click nor a successful tool return as proof of download. Check Downloads for a new file, including numbered duplicate names, then verify its page count, size, hash when comparing copies, and local readability before reporting success. If one supported path fails or redirects to a CDN page showing `ERR_BLOCKED_BY_CLIENT`, inspect the native browser state and try other supported UI download controls before marking the file inaccessible; record the actual outcome.
- If a file still cannot be downloaded after the supported download paths above, tell me which file failed and why. Save the failure and attempted steps in that lecture's run report before stopping; if no lecture can be identified, save them in `course-run-report.md` and link it from `run-report.md`.
- If the course has no lectures yet, digest any accessible files that appear related to the course in a clearly labeled course-materials HTML file. Do not invent lecture numbers or titles. Save a run report describing which files were considered, read, skipped, or inaccessible, even if no digest can be completed; use `course-run-report.md` and link it from `run-report.md`.
- Give every lecture a unique, stable lecture ID and a distinct output file such as `lecture-1.html` or `lecture-2.html`. For a lecture-level request, never overwrite a prior lecture's HTML or combine multiple lecture digests into one file. Update only the requested lecture file, the navigation-only `study-guide.html` index, and cross-links between completed lecture files. Preserve earlier lecture content and its source links.
- Give each lecture its own run-report file using the same stable lecture ID (`lecture-1-run-report.md`, `lecture-2-run-report.md`, etc.). Never overwrite another lecture's report or combine lecture-level findings into one report. Preserve earlier lecture reports; update only the requested lecture's report and the navigation-only `run-report.md` index. Link the lecture reports to one another so their source coverage, download outcomes, verification, and changes can be compared. Keep superseded attempts within the affected lecture's report, clearly labeled with their later resolution.

- Do not treat text extraction alone as proof that image-based formulas, diagrams, or tables were read. Check those elements from the downloaded file using appropriate local document tools.
- If any page or slide cannot be processed, mark the affected lecture incomplete and identify the gap. Do not present a partial digest as complete or invent missing content.
- Keep files within `studio/sgcjin/`. Paraphrase rather than reproduce full course materials. Do not commit or share downloaded course files. Share the generated guide only as required for the studio submission.
