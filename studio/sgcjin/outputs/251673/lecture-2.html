1. An agent connects perception to action

An agent receives percepts from sensors and changes its environment through actuators. Its program repeatedly perceives, decides, and acts. The architecture is the physical or computing platform; the program is the decision logic running on it. A human uses senses and limbs; a robot may use cameras and motors. pp. 2–7

Environment→ percepts / sensors →Agent program on architecture→ actions / actuators →Environment

An agent function maps a percept history to an action. The two-room vacuum cleaner can observe its location (A or B) and whether the current room is dirty; it can move Left or Right, Suck, or do nothing. The slide's sample table maps [A, dirty] to Suck and [A, clean] to Right. A later action may depend on earlier percepts, so a full specification maps percept sequences, not merely the latest observation. pp. 8–9

Recall: Sensors supply evidence; actuators make choices consequential. The program implements the mapping between them.

2. Rationality depends on the task

A rational agent chooses an action expected to maximize its performance measure, given its percept sequence and built-in knowledge. This is an ex ante standard: a rational choice may still turn out badly because the world is uncertain. To judge a choice, specify the success measure, prior knowledge, available actions, and percepts so far. Computational limits also matter. pp. 2, 10–11

a* = arg maxa ∈ A E[U | h, K, a]

This is explanatory notation for the slide's verbal rule, not a formula printed in the deck. A is the available action set; h is the percept history; K is prior knowledge; U is performance under the task's measure; and a* is the chosen action.

For the vacuum, “Suck” is sensible when the observed room is dirty under a cleanliness measure. If energy or battery life also counts, a policy that repeatedly crosses already clean rooms may perform poorly. The performance measure determines what “right” means. pp. 8–11, 15–16

3. Write PEAS before designing the program

PEAS specifies the task environment: Performance, Environment, Actuators, and Sensors. It describes the problem the agent must solve; the agent design is the solution. p. 12

Self-driving carP: safety, travel time, legal driving, comfort.
E: roads, other cars, pedestrians, signs.
A: steering, accelerator, brakes, signals, horn.
S: cameras, sonar, GPS, speedometer, odometer, accelerometer, engine sensors, keyboard. pp. 13–14
Robot vacuumP: cleanliness, travel efficiency, battery life, security.
E: room surfaces, furniture, obstacles.
A: wheels, brushes, vacuum extractor.
S: camera, dirt, cliff, bump, and infrared wall sensors. pp. 15–16

Ask which observations are actually available before assuming the agent knows the full state. A cliff sensor, for example, tells the vacuum about a nearby drop; it does not reveal the layout of the whole home. pp. 16–17

4. Environment properties shape the design

These dimensions describe different difficulties, and one environment can be characterized on each axis. pp. 17–20

Observable?Fully observable means sensors reveal the relevant complete state; otherwise the agent must reason with missing information.
Deterministic?If an action fixes the next state, it is deterministic. Random outcomes are stochastic; choices by other agents can make the setting strategic.
Static?A static world waits while the agent deliberates. In a dynamic world it changes; in a semidynamic one the world stays put but the score changes with time.
Discrete?States, percepts, and actions may be distinct and countable, as in checkers, or vary continuously, as in vehicle motion.
Single agent?Other agents can cooperate or compete, changing what counts as a good action.
Known?If the rules or effects of actions are unknown, the agent must learn them while deciding.

The slide's classification table places the 8-puzzle as fully observable, single-agent, deterministic, static, and discrete; a car is partially observable, multi-agent, stochastic, dynamic, and continuous. These labels depend on the chosen abstraction. p. 19

ChatGPT case study: the slides model typed prompts as percepts, displayed replies as actions, and answer quality, speed, relevance, and safety as parts of performance. They classify the conversation as cooperative and stochastic because the user's next turn is not controlled by the model. The deck also calls the task continuous despite discrete text input and output; that is a modeling choice about the open-ended discourse, not the literal token representation. Its observability classification is likewise conditional on what counts as relevant state. pp. 21–23

5. Four ways an agent can choose

Simple reflex→ + world model →Model-based→ + goal →Goal-based→ + utility →Utility-based

Simple reflex: use the current situation only, as in “if current square is dirty, suck.” Model-based: maintain an internal account of how the world changes on its own and in response to actions. Goal-based: consider future states and select actions that reach a specified goal. Utility-based: compare outcomes with a utility or performance score, useful when goals can be reached in several ways or trade-offs matter. Learning can improve any of these programs from experience. p. 24

The progression adds decision information, but it is not a claim that every utility-based agent is automatically rational or that a reflex agent is always inadequate. Rationality is assessed against its actual task and information. pp. 10–11, 24

6. Choose the right state representation

Atomic: treat each state as an indivisible item; a route-finding state can simply be “in city B.” Factored: describe a state with variables and values, such as GPS location and fuel level. Structured: represent objects and relations between them, such as which road connects which cities. The diagrams move from city nodes, to variable panels, to networks of related objects. Expressiveness increases, but so does the information the program must manage. pp. 25–27, 29–31

The lecture associates atomic states with search and games, factored states with constraints and Bayesian networks, and structured states with first-order logic and language understanding. These are examples of useful pairings, not exclusive rules. pp. 25–27

Self-check

1. Why does the agent function take a percept sequence?

The current observation may omit information seen earlier. A history lets the decision rule use past evidence. pp. 8–10

2. What four details do you need to judge whether an action is rational?

The performance measure, prior knowledge, possible actions, and percept sequence to date. p. 11

3. Give PEAS for a robot vacuum.

Performance: cleanliness, efficiency, battery life, security; environment: rooms, surfaces, obstacles; actuators: wheels, brushes, extractor; sensors: dirt, cliff, bump, camera, infrared. pp. 15–16

4. How can an environment be static but still penalize slow decisions?

It is semidynamic: the world does not change while the agent thinks, but the performance score does. p. 17

5. When is a goal insufficient compared with utility?

When several outcomes reach the goal but differ in cost, risk, comfort, or another valued quality. Utility compares them. p. 24

6. What changes from an atomic to a factored state?

Instead of treating each state as a black box, the agent can inspect named properties and their values. pp. 25–26
