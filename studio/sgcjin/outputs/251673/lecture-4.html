Lecture 4: Uninformed Search

Choose what to expand next using only the problem definition: initial state, successors, path costs, and a goal test. The frontier order determines what guarantee and resource cost you get.

Lecture outline

  1. Five search strategies and the meaning of a frontier.
  2. Breadth-first search and depth-first search: shallowest versus deepest.
  3. Depth limits and iterative deepening: control memory without knowing the solution depth.
  4. Uniform-cost search: use path cost when edges have different weights.
  5. Trace the algorithms on graphs and compare completeness, optimality, time, and space.

Start with the search model

A frontier holds generated nodes waiting to be expanded. Expanding a node tests it for the goal and generates its successors. A graph search also remembers explored states so cycles and duplicates do not keep returning. The lecture’s BFS, DFS, and UCS pseudocode differs mainly in how the frontier selects a node: FIFO queue, LIFO stack, or minimum path cost heap. PDF pp. 4, 9, 26.

Symbols. b = branching factor (up to b children per node); d = depth of the shallowest solution; m = maximum search depth; L = depth limit; g(n) = accumulated cost from the start to node n; C* = optimal solution cost; ε = positive lower bound on every action cost. A complete search finds a solution when one exists under its stated assumptions. An optimal search returns a minimum-cost solution. PDF pp. 5, 10, 13–14, 20, 25, 28.

Breadth-first search (BFS)

BFS removes the oldest frontier entry, so it finishes a shallower layer before visiting a deeper one. With finite b, it is complete. It is optimal when each action has the same cost: the first goal at the least depth then also has the least cost. The lecture gives time and space as O(bd); if the goal test waits until expansion, the frontier can reach O(bd+1). PDF pp. 3–5.

The advantage is a guaranteed shallowest solution under those assumptions. The cost is memory: with b = 10, one million nodes processed per second, and 1,000 bytes stored per node, the slide’s depth-16 row reaches about 10 exabytes and 350 years. The exact figures are an illustration of exponential growth, not a practical runtime forecast. PDF pp. 6–7.

Depth-first search (DFS)

DFS removes the newest frontier entry and follows one branch down before backtracking. A stack needs only the current path and unexpanded siblings, O(bm) space, versus BFS’s exponential frontier. Its worst-case time is O(bm). It can disappear into an infinite-depth branch, and it may find an expensive or deep goal before a better one. In finite spaces, the lecture treats it as complete. PDF pp. 8–12.

Use DFS when memory is the dominant constraint and a quick answer may be enough. In the lecture’s depth-16 comparison, DFS needs about 156 KB versus BFS’s 10 exabytes under the illustrated assumptions. PDF pp. 11–12.

Depth-limited search (DLS)

DLS is DFS that stops generating successors at depth L. That prevents an infinitely deep descent, but a solution deeper than L is missed. The lecture therefore marks DLS incomplete and non-optimal, with time O(bL) and space O(bL). A useful limit can come from problem knowledge; the slide uses a city-route bound as its example. PDF pp. 13–14.

A depth cutoff is different from proving no solution exists. In an implementation, keep “cutoff” separate from “failure” so iterative deepening knows whether a larger limit may help.

Iterative-deepening search (IDS)

IDS runs DLS at limits 0, 1, 2, … until it reaches a goal or establishes failure. Each iteration starts over, but the deepest layer has most of the nodes. It inherits BFS’s completeness and shallowest-solution guarantee under finite branching and uniform step costs, while storing only O(bd) nodes. Its total time remains O(bd). PDF pp. 15–22.

For the slide’s binary tree with a goal at depth 3, the passes generate 1 + 3 + 7 + 15 = 26 nodes; a single complete pass to depth 3 generates 15. The observed overhead is 26/15 ≈ 1.73×. At b = 10 the slide gives 1,234 versus 1,111, or about 1.11×. This is repeated work in exchange for much smaller memory use. PDF pp. 16–24.

The slides derive a loose constant bound C = (1 − 1/b)−2 on repeated work for b > 1. It is independent of d; for b = 2 the bound is 4, although the depth-3 example is only 1.73. PDF pp. 22–24.

Uniform-cost search (UCS)

When edges have different costs, a shallow path need not be cheap. UCS removes the frontier node with the smallest g(n), using a priority queue, and updates a frontier state if a cheaper path to it is found. With a finite-cost solution and every step costing at least ε > 0, it is complete and optimal. It tests a goal when that node is removed at minimum cost; simply generating a goal would be too early. The lecture bounds time and space by O(b⌈C*/ε⌉). PDF pp. 25–29.

The Chicago example makes the distinction concrete. BFS takes the two-edge route Chicago → Duluth → Sault Ste. Marie, costing 157 + 110 = 267. UCS takes three edges through Pittsburgh and Toronto, costing 81 + 80 + 90 = 251. Fewer steps are not necessarily cheaper. PDF p. 27.

UCS expands outward in cost order in every direction; it has no knowledge of where the goal lies. That can make it expensive even while it gives the right cost guarantee. PDF p. 29.

The slides’ heap update is the key mechanism: a frontier node’s priority can decrease when a cheaper route is discovered. PDF pp. 49–59.

The final map examples repeat the lesson with Las Vegas as start and Calgary as goal: BFS and DFS follow their depth rules, while UCS follows accumulated route cost. The visit sequences differ substantially before reaching Calgary. PDF pp. 60–62.

Self-check

  1. Why does BFS return a shallowest solution, and when does that also mean cheapest?
  2. What does a depth cutoff tell IDS that ordinary failure does not?
  3. Why can IDS revisit the root many times yet still take O(bd) time?
  4. In the weighted graph, why does UCS prefer S → C → E → B → G over the two-edge BFS route?
  5. For UCS, why must every action cost at least ε > 0 in the completeness claim?
Review answers
  1. FIFO visits depth layers in order; least depth means least cost only when step costs are uniform.
  2. A cutoff means a deeper solution may exist, so increase the limit.
  3. The bottom layer dominates the node count; repeated upper layers add a bounded factor when b > 1.
  4. Its total cost is 14, versus 15 for S → B → G.
  5. A positive lower bound limits how many steps can fit below any finite solution cost, so UCS cannot endlessly expand cheaper partial paths.
